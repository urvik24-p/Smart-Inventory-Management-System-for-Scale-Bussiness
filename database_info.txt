3. TABLE DEFINITIONS (DDL)
--------------------------------------------------------------------------------

  TABLE: products
  Java Entity: Product.java
  Purpose: Stores product catalogue (one row per product model)

  CREATE TABLE products (
      product_id   INT AUTO_INCREMENT PRIMARY KEY,
      product_name VARCHAR(255) NOT NULL,
      category     VARCHAR(255),
      brand        VARCHAR(255),
      created_at   DATETIME DEFAULT CURRENT_TIMESTAMP
  );

  Columns:
  Column       | Type             | Nullable | Notes
  -------------|------------------|----------|----------------------------------
  product_id   | INT (PK, AI)     | NO       | Auto-increment primary key
  product_name | VARCHAR(255)     | NO       | Product model name
  category     | VARCHAR(255)     | YES      | Product category
  brand        | VARCHAR(255)     | YES      | Manufacturer / brand name
  created_at   | DATETIME         | YES      | Record creation timestamp


  TABLE: serial_numbers
  Java Entity: SerialNumber.java
  Purpose: Each row = one physical unit of a product

  CREATE TABLE serial_numbers (
      serial_id     INT AUTO_INCREMENT PRIMARY KEY,
      product_id    INT NOT NULL,
      serial_number VARCHAR(100) NOT NULL UNIQUE,
      status        ENUM('available', 'sold', 'damaged') NOT NULL DEFAULT 'available',
      created_at    DATETIME DEFAULT CURRENT_TIMESTAMP,
      FOREIGN KEY (product_id) REFERENCES products(product_id)
  );

  Columns:
  Column        | Type                                  | Nullable | Notes
  --------------|---------------------------------------|----------|----------------------------
  serial_id     | INT (PK, AI)                          | NO       | Auto-increment primary key
  product_id    | INT (FK > products.product_id)        | NO       | Links to the parent product
  serial_number | VARCHAR(100) UNIQUE                   | NO       | Unique identifier per unit
  status        | ENUM('available', 'sold', 'damaged')  | NO       | Default: available
  created_at    | DATETIME                              | YES      | Record creation timestamp

  Status Enum Values:
    available : Unit is in stock and ready for sale
    sold      : Unit has been sold to a customer
    damaged   : Unit is damaged / unusable


  TABLE: stock_transactions
  Java Entity: StockTransaction.java
  Purpose: Header record for each stock movement event (IN or OUT)

  CREATE TABLE stock_transactions (
      transaction_id   INT AUTO_INCREMENT PRIMARY KEY,
      transaction_type ENUM('IN', 'OUT') NOT NULL,
      reference_note   VARCHAR(255),
      created_at       DATETIME DEFAULT CURRENT_TIMESTAMP
  );

  Columns:
  Column           | Type               | Nullable | Notes
  -----------------|--------------------|----------|-------------------------------------
  transaction_id   | INT (PK, AI)       | NO       | Auto-increment primary key
  transaction_type | ENUM('IN', 'OUT')  | NO       | IN=stock received, OUT=stock sold
  reference_note   | VARCHAR(255)       | YES      | Free text: PO number, customer, etc.
  created_at       | DATETIME           | YES      | When the transaction was recorded


  TABLE: stock_transaction_items
  Java Entity: StockTransactionItem.java
  Purpose: Line items — one row per serial number moved in a transaction

  CREATE TABLE stock_transaction_items (
      item_id        INT AUTO_INCREMENT PRIMARY KEY,
      transaction_id INT NOT NULL,
      product_id     INT NOT NULL,
      serial_id      INT NOT NULL,
      quantity       INT NOT NULL DEFAULT 1,
      FOREIGN KEY (transaction_id) REFERENCES stock_transactions(transaction_id),
      FOREIGN KEY (product_id)     REFERENCES products(product_id),
      FOREIGN KEY (serial_id)      REFERENCES serial_numbers(serial_id)
  );

  Columns:
  Column         | Type                                            | Nullable | Notes
  ---------------|-------------------------------------------------|----------|------------------------------
  item_id        | INT (PK, AI)                                    | NO       | Auto-increment primary key
  transaction_id | INT (FK > stock_transactions.transaction_id)    | NO       | Parent transaction header
  product_id     | INT (FK > products.product_id)                  | NO       | Product being moved
  serial_id      | INT (FK > serial_numbers.serial_id)             | NO       | Specific physical unit moved
  quantity       | INT                                             | NO       | Always 1 per serial row


  TABLE: users
  Java Entity: AppUser.java
  Purpose: Login credentials and role management

  CREATE TABLE users (
      user_id    INT AUTO_INCREMENT PRIMARY KEY,
      username   VARCHAR(50) NOT NULL UNIQUE,
      password   VARCHAR(255) NOT NULL,
      role       ENUM('ADMIN', 'STAFF') NOT NULL,
      created_at DATETIME DEFAULT CURRENT_TIMESTAMP
  );

  Columns:
  Column     | Type                   | Nullable | Notes
  -----------|------------------------|----------|--------------------------------------
  user_id    | INT (PK, AI)           | NO       | Auto-increment primary key
  username   | VARCHAR(50) UNIQUE     | NO       | Unique login name
  password   | VARCHAR(255)           | NO       | BCrypt hashed — never plain text
  role       | ENUM('ADMIN', 'STAFF') | NO       | ADMIN=full access, STAFF=limited
  created_at | DATETIME               | YES      | Account creation timestamp

  Role Enum Values:
    ADMIN : Full access — can manage products, transactions, users
    STAFF : Limited access — view and record stock movements

4. ENTITY RELATIONSHIPS (ERD Summary)
--------------------------------------------------------------------------------

  products (1) -------------------- (*) serial_numbers
    One product has many physical serial-numbered units.

  products (1) -------------------- (*) stock_transaction_items
    A product can appear in many transaction line items.

  serial_numbers (1) -------------- (*) stock_transaction_items
    A single serial number can appear in multiple transaction records
    (e.g., stocked IN, then sold OUT).

  stock_transactions (1) ---------- (*) stock_transaction_items
    One transaction has one or more line items.
    Cascade: saving a transaction saves all its items automatically.

  users -- standalone table, no foreign key relationships.

  Diagram:

  [users]  (standalone)

  [products] ----< [serial_numbers] ----< [stock_transaction_items] >---- [stock_transactions]
